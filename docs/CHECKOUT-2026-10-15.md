# Checkout and email fixes — 15 October 2026

Prepared for GitHub release on 15 October 2026. Includes the checkout fixes and user-approved prices: standard $4.99 / ₹499; premium $11.99 / ₹599. No production credentials were read or changed. Other fixed currency prices are unchanged.

## Changes

- Updated USD/INR pricing across the price table, country defaults, page metadata and checkout. Standalone expert edit now uses the same premium price table and localized display as preview checkout. Unsupported currencies correctly fall back to USD.

- Checkout receives the public Razorpay key from the same server configuration that creates the order. This prevents a stale browser build key from selecting a different account. Both standard and standalone expert checkout retain the PixPassVisa display name. The actual merchant/UPI name still needs checking in the connected Razorpay account.
- Signed-in customers stay with the current photo and see payment success and download controls. They are no longer redirected to the dashboard.
- Separate opening, checkout, verification, pending and success states; inline errors; double-click guard; modal cancellation cleanup; checkout-script timeout; verification retry without creating another order; per-photo receipt recovery after refresh.
- The expert modal passes its selected plan explicitly, avoiding stale React state.
- Repeat verification returns the secure download token, including when the webhook marked the photo paid first. Browser and webhook token creation are atomic so simultaneous confirmations cannot invalidate one another's links.
- Delivery emails run through Next.js `after` after payment verification returns. Failed provider responses enter the failure logging path rather than being recorded as sent. Webhook delivery links include the secure token.
- Reply-to is optional. Missing API key/sender and provider failures return controlled failures. A valid Resend key and verified sender are still required.
- The send-email prompt is now an in-page email form with sending/result states. Customers with the secure download token or account ownership can correct their delivery address. Otherwise the endpoint only resends to the address already registered to the order. Invalid addresses and expired photos are rejected with useful messages.
- The preview page no longer exposes download tokens merely because someone knows a photo ID. Successful checkout preserves its token in the current URL. Photo components reset when navigating between IDs.
- Small success/form entrance animations and progress spinners respect reduced-motion preferences.

Covers signed-in success, webhook-first verification, invalid signatures/order mismatch, duplicate clicks, network failure/retry, refresh recovery, expert-plan selection, email authorization/errors and concurrent token creation.
- `npm run test:seo`: 17 passing existing tests.
- `tsc --noEmit`: passed.
- `npm run build`: passed, 258 pages generated. Used a random process-only `NEXTAUTH_SECRET` for the local build; no production credentials were changed. The Windows compiler required execution outside the filesystem sandbox.
- Patch applicability: `git apply --check` passed against `release-2026-10-12`.
- Live charge, real inbox delivery, merchant account identity and production webhook configuration have not been tested.

## Live configuration and release checks

1. In Vercel, confirm `RAZORPAY_KEY_ID` and `RAZORPAY_KEY_SECRET` belong to the intended PixPassVisa account and environment. Never paste secrets into chat. Check the Razorpay account's merchant/business name if Postryx still appears; changing the website label cannot change the underlying merchant identity.
2. Confirm the webhook points to `https://www.pixpassvisa.com/api/webhooks/razorpay`, its configured secret matches `RAZORPAY_WEBHOOK_SECRET`, and payment-captured/order-paid events are enabled.
3. Confirm `RESEND_API_KEY`, `RESEND_FROM_EMAIL`, and the sender domain's verified status in Resend. `RESEND_REPLY_TO` is now optional. Inspect Resend rejection logs if delivery still fails; an accepted API request does not establish inbox delivery.
4. Review and deploy the patch through the current GitHub/Vercel release path. Validate in Razorpay test mode with guest and signed-in purchases, cancellation, double clicks, a verification network interruption, refresh recovery, downloads, and email delivery. Confirm the actual live merchant name before a controlled live purchase.
