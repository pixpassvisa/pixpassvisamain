## Findings in the implementation

1. **Trust claims exceeded the evidence.** The previous homepage included a 4.9 rating, 17,000+ applicants, guaranteed compliance, and a 99.8% acceptance rate. Rating counts were hard-coded into structured data. Artificial activity components were present. There was no supporting measurement in the supplied exports. Replaced the homepage messaging, removed aggregate ratings, and disabled artificial activity components. Genuine reviews must have provenance before being used as social proof.
2. **Photo editing claims require document-specific care.** The homepage previously presented background editing as universally compliant. UK digital passport guidance requires an unaltered photo; US guidance also calls for the original unedited photo. Added an independent-service explanation and source links. The existing processing pipeline has not been certified against every authority and must not be advertised as guaranteed acceptance.
3. **Duplicated URL handling was inconsistent.** German `/de/ratgeber/...` routes rendered the same guide as `/de/guides/...`. Added permanent redirects. Corrected `/photo-for-american-visa` to the visa destination. Preserved established URLs with impressions rather than indiscriminately deleting pages.
4. **Sitemap maintenance depended on generated output rewriting.** Replaced the static sitemap/post-build manipulation with a Next.js sitemap route, a generated public-route manifest, canonical route resolution, and published article sources. Only meaningful content dates are emitted. No blanket “updated today” dates.
5. **Private and API pages lacked consistent indexing controls.** Added `X-Robots-Tag` and private cache controls to account/preview routes. Robots permits crawling private HTML so crawlers can observe noindex; this is not access control. Backend responses receive noindex headers separately.
6. **The public interface diluted the main task.** The homepage was long and repetitive, with many overlapping keyword links and broad promises. Replaced it with a concise workflow, country choices, task-oriented tools, visible pricing, plain FAQs, and a distinct visual identity. Shared header/footer and application colors carry the design into the tools.
7. **Branding and photos.** The new interface consistently uses pixpassvisa.com. The source scan found the retired domain only in an obsolete rebranding script, which was removed. Replaced homepage and shared country-page hero photos with a new original illustration; kept technical diagrams rather than silently representing them as verified new examples. See ASSET-PROVENANCE.md.
8. **Host choice.** Existing indexed pages and canonical tags use `https://www.pixpassvisa.com`. Preserved that host and the apex-to-www redirect. “pixpassvisa.com” is the visible brand; changing the canonical host would introduce a separate migration without a demonstrated benefit.

## Remaining work that a code change cannot establish

- Inspect Search Console Pages, Sitemaps, Manual Actions, Security Issues, Core Web Vitals, and representative URL Inspection results. The supplied files contain performance data only.
- Review the full content library against current issuing-authority requirements, especially German digital capture, French ePhoto, Canadian studio requirements, and passport versus visa distinctions. Original localized/editorial text may retain claims requiring review; the technical changes are not certification of that content.
- Compare overlapping articles using query-to-page data before merging them. Similar titles alone do not prove harmful keyword cannibalization.
- Verify production MongoDB content for older domain references, images, or claims. A local source scan cannot modify database-only records or text embedded in raster images.
- Verify Render latency and model warmup using actual request logs. Do not assume the hosting provider itself is the ranking cause. Consider an always-on service only if measured cold starts hurt completion and the owner approves the cost.
- Add useful original evidence: real screenshots from the checker, tested limitations, dated source reviews, support details, and consented real customer feedback. Do not buy links or manufacture reviews.

## Deployment and measurement

Use the existing GitHub → Vercel frontend and GitHub → Render backend deployments. See DEPLOYMENT.md. This change set does not change DNS, purchase hosting, charge a payment, or submit a search-engine indexing request.

After deploying, inspect the homepage, UK page, Australian checker, one guide, and one localized page in Search Console. Submit `https://www.pixpassvisa.com/sitemap.xml` once. Verify the rendered canonical, status, and page content; request indexing for the materially changed priority URLs. A sitemap submission is a discovery aid, not a ranking guarantee.

Track 28-day non-brand clicks and impressions by country, device, query cluster, and landing page. Also track upload starts, validation completion, preview creation, checkout starts, and verified purchases. Compare equal-length periods and avoid declaring success from a handful of impressions. Reassess titles and content after adequate impressions accumulate; do not repeatedly change URLs while Google recrawls.
